## Business Entity Engine [EN](README.md)

Business Entity Engine - самостоятельно разворачиваемая платформа для построения баз знаний на бизнес-объектах, где основная модель данных строится вокруг полного графа бизнес-сущностей.

## Текущие фичи

Текущее приложение - это система на ASP.NET Core / Blazor Server, в которой есть:

- пространства как верхний рабочий контекст;
- папки, документы и рич-документы как бизнес-сущности;
- возможность хранить бесконечные тексты в рич-документах (ограничено только ресурсами вашей БД);
- возможность заливать картинки, видео, аудио и встраивать их в страницы;
- аутентификация через Authentik;
- администрирование пользователей, ролей, групп и прав доступа на уровне пространства;
- deployment assets для Docker Compose;

## Философия бизнес-объектов

Данная система хранит информацию в такой штуке, как бизнес-объект. Бизнес-объекты обладают коммутативностью, т.е. могут быть вставлены в друг друга (embed) или образовывать приложения, которые существуют внутри бизнес-энтити.

Приложения могут быть частью сборки, или же поставляться внутри плагинов. Механизм плагинов и приложений сейчас разрабатывается.

## Политика в области ИИ

Данный продукт на 99% написан через ИИ (windsurf, codex, claude), и автор планирует продолжать так и дальше. Автор не является вайбкодером и понимает все, что происходит в коде, все технологии и процессы.

Все инструкции, используемые в промптинге, находятся в папке Context.

## Статус проекта

Business Entity Engine находится на этапе публичной инкубации / preview.

На этом этапе платформа намеренно остается максимально открытой для практической обратной связи. Ее можно ставить, форкать, менять, тестировать, использовать для прототипов, писать плагины и проверять на реальных сценариях.

Важные замечания preview-этапа:

- API, storage layout, скрипты развертывания и механики миграции могут меняться.
- Это еще не отполированный production-дистрибутив.
- Безопасность, backup, storage и модель прав доступа еще укрепляются.
- Механизмы плагинов и приложений еще не разработаны.
- Перед выставлением инстанса в сеть надо внимательно проверить конфигурацию и secrets.

## Первый запуск из репозитория

Authentik и кабинет пользователей устанавливаются отдельно комплектом User Hub.
BusinessEntity использует внешний OIDC и сохраняет собственные роли, группы и права.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# Укажите issuer, client ID/secret, проверенный subject первого администратора
# и USER_HUB_URL. Секрет OIDC выдаётся при регистрации приложения в Authentik.
docker network create docker-business-entity-common-bridge
docker compose up -d --build
```

Новые установки используют `IDENTITY_INITIAL_PROVISIONING=None` и
`IDENTITY_MANAGED_LOCAL=false`. При заданном `USER_HUB_URL` профиль и управление
пользователями предлагают переход в общий кабинет. Локальные права приложения
остаются в BusinessEntity. Для частного CA настройте доверие сертификату на клиенте
и в контейнере приложения; проверку HTTPS отключать нельзя.

Локальная `.env` исключена из Git. Примеры: [.env.example](.env.example) и
[Deployment/.env.example](Deployment/.env.example). Существующие настройки, база
Authentik и его файловые данные автоматически не переносятся и не удаляются.
Смена issuer требует отдельного плана привязки существующих пользователей.

Локальные адреса приложения и логгера: `http://localhost:7000` и
`http://localhost:5080`. Установка готовой поставки: [Deployment](Deployment/README.md).

## Участие

Репозиторий сейчас находится на раннем этапе публичной инкубации. Основной канал участия - GitHub Issues.

Мы не ожидаем, что люди будут делать pull requests в этот upstream-репозиторий. На текущем этапе проекту нужен feedback, а не внешний поток веток и PR. Форки для экспериментов нормальны, но они должны жить как отдельные неофициальные работы, если явно не согласовано иное.

Особенно полезны issues про:

- проблемы установки;
- обратная связь по deployment;
- bug reports;
- security reports;
- feedback по storage и migration;
- feedback по permission model;
- сценарии редактирования рич-документов;
- эксперименты с plugins и mini-apps.
