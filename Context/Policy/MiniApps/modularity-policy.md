# Модульность страниц и оболочки

Норма TASK_ARCH_001 v2.2. Runtime реализован этапом 4; оболочка и страницы переведены этапом 5.

## Декларации и создание

MiniAppHostService — singleton на миниапп, отвечает на GiveMeModuleDefinitions.
Он объявляет возможности, не читает данные, не создаёт UI и не исполняет команды.

ModuleCatalog собирает определения и создаёт фоновые runtime-модули.
WindowModularityManager управляет модулями конкретного окна/circuit.
ModuleId создаёт менеджер. MiniAppId обозначает владельца домена,
ModuleDefinitionId — объявленный вид модуля, ContextId — предметный контекст.

## Размещение

Поддерживаются Headless, ShellModuleHostArea и Page.
Внутренние вкладки, WorkspaceTab и TabbedHostArea не используются.
Обычный модальный диалог при необходимости не становится системой вкладок.

Места оболочки: LeftNav, TopBar, LeftTree, @Body и RightPanel.
RightPanel содержит обычные секции. Администрирование — разделы-страницы.

## Компоненты

ComponentKey регистрируется рядом с владельцем через AddModuleComponent.
Фабрика использует реестр; неизвестный обязательный ключ и дубликат дают отказ.
По шине не передаются Type, RenderFragment, Razor-компоненты или ICommand.
Page-host содержит URL, guard и PageModuleHost. Auth/error/печать сохраняют
необходимую инфраструктуру хоста.

## Состояние и жизненный цикл

Рабочий экземпляр миниаппа может иметь несколько UI-модулей и один EditSessionId.
Dirty принадлежит этому контексту, а не отдельной копии состояния компонента.
Переход по странице завершает прежний модуль после разрешения guard.
Постоянные места оболочки продолжают жить в своём окне.

Opened, Activated, Deactivated, Closed передаются по общей адресной шине.
Подписки освобождаются при завершении. Reconnect и prerender не создают
двух обработчиков одного адреса. Жизненный цикл отражается в веб-логгере.

Источник: [ТЗ §3.3–3.6](../../Tasks/TASK_ARCH_001_miniapp-bus-architecture-migration.md).

## Запуск и снятие UI

ModuleCatalog — hosted service: сначала CollectAsync по шине, затем headless
runtime в порядке деклараций. Scope каждого фонового модуля удерживается до Stop.
Host-service содержит только объявления; локальная RuntimeRegistration связывает
ключ с фабрикой владельца. Программа не инициализирует миниаппы вручную.
Список фактических стартовых модулей и порядок — в реестре миниаппов.

WindowModularityManager создаёт ModuleId. PerContext требует ContextId;
два вида UI одного владельца/контекста могут использовать один EditSessionId.
При снятии вспомогательного UI общий черновик остаётся. Последний dirty-модуль
сохраняется неактивным; его команды отклоняются, повторное открытие активирует
тот же рабочий экземпляр. Навигационный guard подключается на этапе 8.

## UI

MainLayout содержит LeftNav/TopBar/LeftTree/Body/RightPanel; правая панель —
обычные секции. User header предоставляет вложенное именованное место
User.HeaderSpaces владельцу пространств. URL/PrintLayout остаются в Pages,
предметное содержимое — Components владельцев. Registry перечисляет фактические
модули/маршруты/доступ. Страница администрирования не импортирует чужие компоненты.

Guard модуля и guard адресной команды выполняются сервером. Для контента
metadata берётся из canonical DataProvider. Страница выбора пространства остаётся
публичной для anonymous сценария по users/content-access policy; это сознательно
отличается от краткой таблицы guard исходного инвентаря ТЗ.


## Master/helper

SelectionPublisher принадлежит master UI; SelectionObserver — каждому helper.
Вначале Tree меняет локальное выделение и планирует render, затем публикует
ObjectInContextSelected. В событии — ImmutableArray value records, окно, источник,
ревизия выделения и поколение активного источника. Менеджер хранит только адрес
master. Helper отвергает чужое окно, закрытый/неактивный источник, старое поколение
и нерастущую ревизию. Смена/закрытие источника очищает сведения; поздний helper
запрашивает актуальный снимок по шине. Все подписки имеют lifetime владельца.
Для дополнительных предметных данных используется публичный контракт владельца.
Общего изменяемого TreeSelectionService и прямой передачи VM нет.
