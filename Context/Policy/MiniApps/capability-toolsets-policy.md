# Политика capability toolset-ов

Норма TASK_ARCH_001, этап 9. Конкретные toolset-ы этим пакетом не внедряются.

Capability — объявленная возможность выполнить предметную операцию владельца
от доверенного пользователя в определённом контексте. Это поверхность над уже
существующими публичными контрактами, а не новый доступ к внутренним сервисам.

## Декларация

Владелец объявляет устойчивый ID, назначение, типизированные вход/выход,
предметный контекст, требуемое право, возможность изменения данных и порядок
получения исхода. Контракт не содержит Razor, delegates, IServiceProvider,
DbContext, repository, файловых путей canonical storage или object-конверта.

UI-команда, API adapter и будущий toolset используют один предметный сценарий
владельца. Копировать алгоритм в адаптер запрещено. Межминиаппное исполнение
проходит по общей шине. Общие движковые возможности остаются в Core/Infrastructure.

## Адрес и доступ

UserId и полномочия устанавливает сервер. Для работы с текущим редактором нужны
LogicalWindowId, живой ModuleId, EditSessionId и ContextId; угадывать окно по UserId
или выбирать случайный circuit нельзя. Вне UI используется явный execution scope.
Скрытие capability в интерфейсе не заменяет проверку права при исполнении.

Замкнутый/устаревший адрес и неизвестная capability дают явный BusError.
Подписки принадлежат владельцу и прекращаются вместе с ним. Read-only capability
не получает полномочие записи просто потому, что вызывает общий transport.

## Изменения и повтор

Если операция меняет локальный набор редактора, изменяется его собственный dirty.
Запись выполняется через Save всего рабочего набора/DataProvider; прямого доступа
к canonical storage нет. Самостоятельная завершённая операция может немедленно
отправлять собственную транзакцию. Глобальные Save/dirty/history пространства
не вводятся.

OperationId сохраняет идентичность принятой операции; таймаут не доказывает
rollback. Проверка durable outcome и повтор одинакового пакета обязательны для
изменяющих операций. Новый ввод не подмешивается в повтор frozen пакета.

Секреты не включаются в сообщения, журналы или durable outcome. Работа с внешним
API описывает свои отдельные эффекты: SQL rollback их не откатывает. Опасное
необратимое действие требует применимого прямого разрешения пользователя;
capability не расширяет исходно предоставленные полномочия.

## При добавлении toolset-а

Зарегистрировать возможности и контракт у владельца, дополнить реестры,
проверить типизированные отказы, права, два окна, lifecycle, отмену ожидания,
повтор OperationId и сохранение новых правок. Не создавать второй transport,
универсальный обход IServiceProvider или адаптер старого API/формата.
