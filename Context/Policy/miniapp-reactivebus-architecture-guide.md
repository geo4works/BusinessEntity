# MiniApp и общая шина сообщений

Норма TASK_ARCH_001 v2.2, 2026-10-28. Шина и коннекторы — этап 1;
полные границы — этап 6. Реестры описывают фактический код.

## Границы и общий слой

MiniApp владеет предметной функциональностью, состоянием и интерфейсом.
Снаружи доступны Contracts; Registration вызывает композиционный корень.
Чужие Internal, Facade, Components, Storage и Repositories запрещены.

Общие модели и движковые сервисы находятся в Core и используются через DI.
Core получает типоспецифичную логику через описатели владельцев.
Из миниаппных контрактов Core может ссылаться только на Contracts DataProvider.
Внутри миниаппа сервисы вызываются напрямую; самозапрос через шину запрещён.

## Один транспорт

Один singleton ReactiveUI.IMessageBus обслуживает всё приложение.
Второй шины окна/circuit нет. По нему проходят данные, декларации,
UI-команды, выделение, dirty и сохранение.

Общие обработчики могут быть singleton. Scoped-обработчик фильтрует адрес
до чтения состояния/выполнения и освобождает подписки. Черновик принадлежит
рабочему экземпляру окна, а не singleton всего типа миниаппа.

## Сообщения и адреса

Command, Event, Request и Response — предметные типизированные records.
Конверт string Type + object Payload и словари вместо полей запрещены.

| Поле | Назначение |
|---|---|
| UserId | Проверенный сервером автор/адресат |
| LogicalWindowId | Окно браузера |
| ModuleId | Конкретный UI/фоновый модуль |
| EditSessionId | Контекст сохранения рабочего экземпляра |
| ContextId | Предметный контекст |
| RequestId | Корреляция ответа |
| OperationId | Идентичность сохраняемой операции |

Одного UserId недостаточно для двух окон. На адресный запрос отвечает
один владелец. Автор берётся из доверенного серверного контекста.
HTTP и фоновые операции не выбирают случайный текущий circuit.
Адресация не заменяет проверку доступа.

События общих данных доступны заинтересованным потребителям;
перед показом проверяются права и контекст. UI обновляется через InvokeAsync.
Prerender, reconnect и повторное создание страницы не дублируют обработчик.

## Коннекторы и ответы

Коннектор — клиент BusRequestClient, без фасада и внутренних кодеков/сервисов.
Он не инициализирует runtime. MessageHandler вызывает свои сервисы напрямую.

Клиент подписывается до отправки, проверяет RequestId, освобождает ожидание
после ответа, отмены и таймаута. Верхний таймаут по умолчанию — 30 секунд.
Отказ — BusError(Code, Message), поднимаемый как типизированное исключение.
Законное отсутствие объекта определяется отдельно от повреждения данных.
Сбор GiveMe… / HereAre… учитывает нескольких владельцев, включая поздние ответы.

## Исход записи

Отмена ожидания и timeout не доказывают откат принятой транзакции.
Исход OperationId хранится в БД вместе с изменениями и доступен после рестарта.
Повтор одинакового пакета не дублирует запись; другой пакет с тем же ID — отказ.
DataProvider публикует изменения после коммита и согласования кэша.
Пользовательская ошибка доставляется один раз с адресом и корреляцией.

## Проверки и реестры

Новые миниаппы и сообщения заносятся в Context/Registry в том же изменении.
Проверяются корреляция/timeout/cancel, два пользователя, два окна одного
пользователя, освобождение подписок, отсутствие самозапросов и обходов границ.
