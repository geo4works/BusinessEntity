# Явные отказы и обязательные данные

Норма TASK_ARCH_001 v2.2, этапы 1–9.

## Основное правило

Обязательное значение читается из одного авторитетного источника.
Его отсутствие, повреждение, неизвестный тип или версия формата дают
типизированный отказ. Запрещены подбор похожего поля, пустой объект вместо
повреждённого payload и молчаливое повторение через другую реализацию.

## Контракты

Request завершается результатом или BusError(Code, Message).
Code стабилен и пригоден для локализации; сообщение не раскрывает секреты
и внутренний стек. Законное отсутствие объекта отражается контрактом отдельно.

Null, пустой список и документированное значение новой UI-настройки допустимы,
если это нормальный результат, а не сокрытие ошибки.

## Диагностика

Ошибка операции публикуется пользователю один раз, с адресом и корреляцией.
Повторно ловящий уровень не дублирует уже показанный отказ.
Техническая причина остаётся в журнале с идентификатором операции.
При неопределённом исходе записи показывается этот статус и выясняется
фактический результат; нельзя объявить запись откатившейся по таймауту.

## Форматы и наследие

Совместимость со старыми API, БД, payload и архивами не поддерживается.
Новые адаптеры старых форматов не создаются, существующие удаляются
при изменении своей подсистемы. Неизвестный формат завершается ошибкой.
Внешние особенности браузера/Authentik разрешены, если названы и пояснены.
