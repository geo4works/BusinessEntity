# Восстановление пространства из backup формата 2

Restore создаёт новое пространство в общей БД приложения. Режима merge или
записи поверх исходного пространства нет. Старые схемы и архивы не поддерживаются.

1. Прочитать manifest формата 2, проверить digest каждого Entity JSON, связей и
   файла; не допускать выхода пути за каталог архива или reparse/symlink внутри него.
2. Core GraphArchiveRemapper строит новые идентичности сущностей, чанков, свойств,
   комментариев и связей. Все payload-версии сохраняются; ID payload равен ID
   владельца. Исторические авторы и время сохраняются.
3. Типоспецифичные ссылки перепривязывают IEntityArchivePolicy владельцев.
   Core не знает Document, статьи или видео. EntityUrlPattern регистрирует
   владелец маршрута. Обычные GUID в тексте не заменяются.
4. Для статьи перепривязываются конкретные строки чанков в составах версий,
   внутренние ссылки, видео и anchors чанков. ImageId остаётся локальным ID
   ресурса нового документа. Файлы получают canonical адрес нового владельца.
5. Сформировать один EntitySaveBatch с ImportSnapshot и источниками файлов.
   DataProvider проверяет типы, последовательность версий, точные references,
   свойства, комментарии, Contains и файловые зависимости. Fingerprint и
   производные HTML/PlainText пересчитываются для новых идентичностей.
6. Записать весь граф, файлы и исход OperationId одной операцией. SQL-ошибка или
   ошибка подготовки файла не публикует часть пространства. Отдельного cleanup
   частично сохранённого графа нет.
7. После коммита записать диагностический report с картами ID. Ошибка report
   сообщает предупреждение «пространство восстановлено», не объявляет откат.

Название нового корня задаёт пользователь; по умолчанию добавляется `_restored`.
Название корня в его payload-версиях соответствует новому имени. Остальные
названия, история, составы чанков, комментарии и указатель публикации сохраняются.
Публикация не переписывает payload ни одной версии.

Автоматический backup восстановленного пространства по умолчанию выключен;
папка сбрасывается в стандартную для нового ID, чтобы не перезаписать исходный
архив. Это меняет настройки нового пространства, а не исходного архива.

Таймаут ответа не означает откат: SaveBatch содержит устойчивый OperationId,
исход можно получить из DataProvider. Большие export/import и пакеты файлов
имеют явный timeout ожидания 30 минут; обычные bus-запросы — 30 секунд.
