# Backup пространства: формат 2

Действующая реализация этапа 2 TASK_ARCH_001. Старые архивы не читаются.

BackupRestore получает полный согласованный подграф через типизированный запрос
DataProvider. Прямой доступ к EF, таблицам, репозиториям и canonical файловым
путям запрещён. Временные копии файлов выдаются DataProvider в lease; оркестратор
освобождает его в finally. Видео копируются потоками.

## Состав

Экспорт начинается от Space, проходит исходящие Contains и RelatesTo, исключает
другие пространства. Файловые зависимости всех исторических версий дополняют
подграф: использованное видео входит в backup даже без отдельной связи дерева.

Включаются карточки, все payload-версии с названиями, авторами, временем и
описаниями; все строки чанков и точные составы каждой версии; свойства Entity,
Data и Chunk; комментарии с parent; внутренние связи; публикация из карточки;
manifest и bytes всех постоянных файлов сущности. OperationId исходной системы
не переносится как история действий нового пространства.

## Каталог

```text
manifest.json
entities/{type}--{id}--{name}/data/{snapshot-sha256}.json
entities/{type}--{id}--{name}/files/{content-sha256}.blob
relations/{snapshot-sha256}.json
```

Entity JSON — полная ArchivedEntity, без EF DTO и путей исходной машины.
Manifest содержит FormatVersion=2, RootEntityId, SavedAt, список EntityId +
RelativePath + ContentHash, RelationsPath и RelationsHash. Ссылка на файл хранится
как относительный ArchiveEntry. Для текущего переносимого формата обязательны
все поля контрактов; неизвестные поля и форматы отклоняются.

Имя папки санитаризуется и ограничивается по длине. Идентичность определяет ID,
а не имя. Restore читает только manifest и перечисленные им файлы.

## Публикация и изменения

DataProvider держит writer gate и repeatable-read SQL-снимок до завершения
подготовки временных файлов. Постоянные файлы неизменяемы.

Backup сравнивает digest полного состояния сущности, включая комментарии,
публикацию и описания версий. LastModified карточки не служит признаком полноты.
Неизменившиеся snapshots повторно не публикуются. Фоновая проверка пока получает
полный экспорт; оптимизация источника изменений относится к кэшу этапа 3.

Новые content-addressed файлы и JSON сначала полностью записываются и проверяются.
Manifest публикуется последним atomic rename с заменой. Ошибка оставляет прежний
manifest и все его файлы читаемыми. Неперечисленные manifest-ом файлы не считаются
опубликованными. Предшествующие immutable snapshots пока сохраняются в каталоге,
чтобы параллельное чтение предыдущего manifest не потеряло свои файлы.

Удаление и переименование отражаются новым manifest; сиротские revisions
физически убираются при явной очистке backup. Самостоятельного удаления истории
или canonical файлов оркестратором нет.

## Расписание и пути

SpaceBackupService выполняет фоновые проверки с отдельным системным scope.
Обычный poll — 30 секунд; интервалы и DoBackup задаются настройками пространства.
Ручной Backup из администрирования проходит тот же алгоритм.

Storage:RootPath обязателен. По умолчанию backup находится в
`{StorageRoot}/backups/spaces/Space--{id}`. Настроенный host-путь bind mount
отображается в container-путь через Storage:HostRootPath. Каталог backup не может
пересекаться с canonical objects, staging, restore reports или корнем storage.

Очистка через явную команду UI допустима только внутри storage, после проверки
manifest и RootEntityId. Физическое удаление storage/volumes исполнителем
раскатки требует явного разрешения пользователя.
