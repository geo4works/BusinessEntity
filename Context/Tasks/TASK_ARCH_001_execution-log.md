## Этап 2 — DataProvider и транзакционное сохранение

Статус: завершён. CMMTP 3 — 0.16.5, коммит 6737db0, push origin/main успешен.

### Сделано

- EntitySaveBatch объединяет карточки, payload, exact chunk references, связи,
  свойства, комментарии, файлы, публикацию, описания и Restore. Один writer gate,
  один DbContext и SQL transaction. Outcome, hash, автор и время OperationId
  сохраняются тем же коммитом; повтор и потерянный ответ проверены после рестарта.
- Создание, переименование, перенос и удаление общего helper, комментарии Activity,
  свойства Space и graph-чтение User переведены на connector/шину. Старые CRUD API,
  отдельный canonical file writer, generic repositories и context pool удалены.
  EF-модели и DbContext закрыты внутри DataProvider.Internal. Собственные служебные
  таблицы User остаются оговорённым исключением.
- Document и статья имеют v1 при создании; изменённый контент/название создают
  полную версию автора. База редактора фиксируется, чужая дельта не подмешивается.
  Состав версии ссылается на точные (ChunkId, ChunkRowVersion), порядок хранится
  отдельно. Восстановление создаёт новый снимок. Publication находится в карточке.
- Неизменяемые файлы готовятся и проверяются до commit ссылок. SQL защищает
  исторические зависимости. Recovery убирает неподтверждённые objects/staging,
  только если БД доступна. Большие видео передаются потоковым временным источником.
- Полный export/restore подграфа через DataProvider включает историю, авторов,
  свойства, comments, exact references и файлы. Backup формата 2 публикует manifest
  последним; restore создаёт новые IDs и весь граф одной операцией. Типовые правила
  перепривязки объявлены владельцами, Core не ветвится по доменным типам.
- Services/EntityMessages удалён, data events публикует только DataProvider после
  commit. Читающие окна обновляются; открытый редактор не перечитывается этим событием.
- Устранены выявленные smoke-ом гонки перерисовки дерева, выбора версии и удаления
  одного пользовательского свойства несколькими окнами. Панель редактора и история
  больше не перекрывают команды в узкой колонке. Импорт формирует текущий manifest.
- Актуализированы storage/version/file/backup политики, реестры и сценарии проверки.

  загружается до запросов. Кандидат строится внутри SQL-транзакции, публикуется

  Размеры являются оценками. На запись выполняется полный metadata reload,
  инкрементальное обновление не заявляется; payload/chunks в граф не загружаются.

  по-прежнему требует PublishedVersion. Print использует имя выбранной версии.
