# TASK_SECURITY_001 — Авторизация скачивания файлов

Дата: 2026-10-29.
Статус: зафиксировано отдельно; реализация не начата.
Источник: итоговый аудит TASK_ARCH_001 и решение пользователя.

## Решение об объёме

Пользователь выбрал: «Зафиксировать отдельно и завершить архитектурную раскатку».
Задача не входит в завершённые этапы 0–9 TASK_ARCH_001 / релиз 0.17.0.
Текущая фиксация не меняет код, правила доступа, БД или файловое хранилище.

## Подтверждённое наблюдение

- Прямой GET собственного smoke-видео по маршруту
  `/media-server-files/videos/{videoId}/original` без cookie вернул HTTP 200.
- `RichTextDocumentFilesController.GetImage` получает файл без запроса прав
  документа через UserMiniApp. Для изображений зафиксирован результат чтения
  кода; отдельная HTTP-проверка анонимного image GET в аудите не выполнялась.
- Это прежний режим раздачи файлов, сохранённый архитектурной раскаткой.
  Проверенные page/command guards и draft/published UI сами по себе его не закрывают.

## Цель отдельной доработки

Согласовать и реализовать правила прямого чтения изображений и видео, чтобы URL
файла не обходил принятые права на связанный контент. Сохранить законное чтение
вложений опубликованных статей и потоковую отдачу разрешённого видео.

## Что уточнить до реализации

1. Режим доступа к самостоятельному видео библиотеки и к видео, встроенному в статью.
2. Доступ anonymous, ViewPublished и ViewDraft к файлам разных версий статьи.
3. Поведение для файлов, используемых несколькими документами/историческими версиями.
4. Ответ при отказе (401/403/404), политика HTTP cache и уже выданных прямых ссылок.

Эти решения пока не приняты; текущий документ не задаёт новую семантику молча.

## Архитектурные ограничения

Права определяет UserMiniApp через публичный контракт. HTTP adapter вызывает
сценарий владельца; DataProvider предоставляет generic данные и файлы, без
чужой предметной логики. Межминиаппное взаимодействие проходит по общей шине.
Не обращаться к чужим Internal/DbContext и не обходить canonical file manifest.
Миграции старых форматов, очистка storage и изменение истории этой задачей
не разрешаются.

## Будущая проверка приёмки

После согласования правил проверить разрешённые/запрещённые прямые GET для
anonymous и разных ролей, published/draft/исторических вложений, удаления и
повторного использования файла. Проверить обычное отображение разрешённых
картинок, video Range и работу без выбранного пространства/cookie.
